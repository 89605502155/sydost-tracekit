# Развёртывание регистратора

Гостевой регистратор — один файл на Python только со стандартной библиотекой:
`src/sydost_tracekit/recorder.py`. Он проверен на Python 3.11–3.14, на которых проходят тесты библиотеки; более ранние версии не проверялись. Он читает procfs Linux.

## Шаги

1. Скопируйте файл в гостевую ВМ, например в `/opt/tracekit/recorder.py`.
2. Проверьте, что отсчёты снимаются, например записью на 1 секунду:

```sh
python3 /opt/tracekit/recorder.py --hz 10 --duration 1 --out /tmp/check.csv
```

3. Запускайте на всё время опыта. Регистратор пишет `<out>.csv` и `<out>.csv.json`
   (сводка: отсчёты, опоздания и пропуски тиков, доля CPU).

## Юнит systemd

```ini
[Unit]
Description=sydost-tracekit guest memory recorder
After=network-online.target

[Service]
ExecStart=/usr/bin/python3 /opt/tracekit/recorder.py --hz 10 --duration 7200 --out /var/lib/tracekit/trace.csv
Restart=no
Nice=19
CPUAccounting=yes

[Install]
WantedBy=multi-user.target
```

Сначала создайте каталог `/var/lib/tracekit`. Запускайте юнит командой `systemctl start` с началом
нагрузки; длительность ограничивает запись.

## Что значит сводка

- `late`: тики, у которых снятие отсчёта началось больше чем через полпериода после срока.
- `skipped`: тики, пропущенные, потому что регистратор отстал на целый период или больше.
  Пропущенные тики не пишутся, поэтому в сетке времени есть разрывы; `recordings_to_trace`
  восстанавливает их между строками.
- `cpu_share`: процессорное время регистратора, делённое на реальное время. Измерьте её на
  запланированной частоте до долгого запуска. Тесты накладные расходы не измеряют.

## Часы

Синхронизируйте часы гостя (например, chrony) до запуска. Времена хоста и гостя сравниваются
через `t_real_s`; погрешность совмещения даёт `estimate_offset`.
