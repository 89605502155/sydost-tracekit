# sydost-tracekit

[English version](README.md) · [Документация](docs/ru/quickstart.md) · [История версий](CHANGELOG.md)

`sydost-tracekit` записывает эталонные трассы памяти виртуальных машин, оценивает накопленный
дефицит памяти по отсчётам с более грубым шагом, даёт границы погрешности этой оценки и
настраивает конфигурацию мониторинга по трассам.

Накопленный дефицит `D = ∫ (d − a)⁺ dt` — интеграл. Отсчёты потребности, удержанные на шаге ℓ,
задают простую функцию, поэтому оценка сходится к `D` при ℓ → 0. Библиотека даёт явные границы
погрешности: `ℓ·V(d)` для удержания (первый порядок) и `ℓ²·(T·M/12 + K·L/3)` для линейной
интерполяции (второй порядок).

Разработано в Брянском государственном инженерно-технологическом университете (БГИТУ),
автор Андрей Ферубко.

## Установка

```sh
pip install sydost-tracekit           # анализ, границы, настройка, командная строка
pip install "sydost-tracekit[kvm]"    # добавляет libvirt-python для сборщика на хосте
uv add sydost-tracekit
```

Гостевой регистратор требует только стандартной библиотеки Python: скопируйте один файл
`src/sydost_tracekit/recorder.py` в гостевую ВМ (см. руководство по развёртыванию).

## Быстрый старт

```python
from sydost_tracekit import deficit_integral, estimate_from_samples, simulate, synthetic_trace

tr = synthetic_trace("A", T=600.0, dt=0.1, seed=7)  # эталонная трасса, шаг 0,1 с
run = simulate(tr, interval_s=4.0)  # выделение контроллера, опрашиваемого раз в 4 с
D = deficit_integral(tr.d, run.alloc, tr.dt)
est = estimate_from_samples(tr.t[::20], tr.d[:, ::20], run.alloc, tr.dt, "linear")
print(f"D = {D:.1f} MiB*s, линейная оценка по отсчётам раз в 2 с = {est:.1f} MiB*s")
```

## Командная строка

```sh
sydost-tracekit record --hz 10 --duration 600 --out trace_vm1.csv   # запустить регистратор здесь
sydost-tracekit integrate ref.csv --alloc alloc.csv --steps 0.5,1,2 # оценить D по отсчётам
sydost-tracekit bound ref.csv --steps 1 --target 1e4               # границы и частота опроса
sydost-tracekit tune train.csv --intervals 1,2,4,8 --alpha 0.5 --dmax 10
```

## Возможности

- **Частота опроса для заданной погрешности.** `plan_sampling` даёт метод и шаг (частоту),
  при которых априорная граница не превышает цель, по константам эталонной трассы.
- **Уточнённая граница для удержания.** `hold_error_bounds_refined` учитывает только вариацию,
  существенную для дефицита (подъёмы потребности над выделением и спады удерживаемого значения
  над ним). Она верна и уже, чем `ℓ·V(d)`; примеры это показывают.
- **Точный интеграл положительной части** кусочно-линейного сигнала по точкам пересечения
  (`positive_part_integral`); ступенчатое выделение — повторённый узел.
- **Гостевой регистратор** только на стандартной библиотеке: расписание без дрейфа, учёт
  опозданий и пропущенных тиков, доля CPU самого регистратора.
- **Совмещение часов хоста и гостя**: смещение по обменам «запрос–ответ» (алгоритм Кристиана,
  погрешность не больше половины времени обмена) и линейный дрейф в ppm.
- **Формат трасс** с проверкой (равномерная сетка, конечные значения, уникальные имена).
- **Настройка**: перебор конфигураций, фронт Парето, выбор при ограничениях `P(θ) ≤ α` и
  `D ≤ D_max`.

## Чем отличается от общих инструментов

| Задача | Общие инструменты | sydost-tracekit |
|---|---|---|
| Интеграл по отсчётам | `scipy.integrate.trapezoid`, пересэмплирование в `pandas` | интеграл **дефицита** `(d − a)⁺` при известном выделении и точная формула по точкам пересечения |
| Погрешность интеграла | нет: границы для дискретного дефицита не дают | явные границы `ℓ·V(d)`, `ℓ²(T·M/12 + K·L/3)` и уточнённая граница для удержания |
| «Какая частота опроса нужна?» | эмпирическое правило | шаг для заданной абсолютной погрешности по трассе |
| Сбор | Prometheus, node_exporter, collectd: по умолчанию опрос раз в 15–60 с | регистратор в госте на 10 Гц с учётом накладных расходов и сборщик libvirt на хосте |
| Настройка | ручные пороги | фронт Парето по стоимости мониторинга, выбор при ограничениях |
